# 产品创意验证 Agent Skill — 市场验证行动指南

> 基于《做对产品》第 4、5、6 章方法论生成  
> 生成时间：2025 年 2 月 11 日  
> 用户输入摘要：帮助创业者、独立开发者或产品经理快速验证产品想法是否可行的 Agent Skill

---

## 一、思考工具：市场假设

本部分对应原著第 4 章（市场参与假说 → 用数字说话 → XYZ 假说 → 缩进假说）。Agent Skill 属于软件/工具类产品，需验证目标用户是否会**使用**、**付费**或**持续依赖**。

### 1.1 市场参与假说（MEH）

**一句话描述你的创意以及市场会如何回应：**

- **创意**：一款 Agent Skill（可在 Cursor、Claude、ChatGPT 等 AI 平台调用的技能），用户输入产品想法后，技能一步到位输出基于《做对产品》的「产品创意市场验证行动指南」，包含思考工具、预型方案、分析工具。
- **MEH**：如果我们能提供一款让创业者、独立开发者、产品经理只需输入产品想法就能快速获得可执行的验证方案的 Agent Skill，那么相当一部分有产品创意、且希望低成本验证的人会愿意使用它、推荐它，甚至为之付费或订阅。

### 1.2 XYZ 假说（用数字说话）

**至少 X% 的 Y 会 Z。**

- **X%**：至少 10% —— 在可触达的测试市场中，预期会采取 Z 行动的比例（有根据的猜测，可随试验修正）。
- **Y**：创业者、独立开发者、产品经理中，经常有新创意、希望先验证再投入、且使用 AI 工具（如 Cursor、Claude、ChatGPT）的人群。
- **Z**：以下**具体行为**之一：（1）**使用**该 Skill 至少 1 次（输入想法并获取指南）；（2）**留已验证邮箱**以获取更新或高级版本；（3）**付费**订阅或一次性购买（如 9～99 元）；（4）**主动推荐**给同事或社群（可观察为转发链接、在群内提及等）。

**模糊表述 → 数字表述对照**

| 模糊表述     | 数字表述                          |
|--------------|-----------------------------------|
| 相当一部分人 | 至少 10% 的 Y                     |
| 愿意使用     | 至少使用 1 次并完成一次验证流程   |
| 愿意付费     | 支付订阅费或一次性购买            |
| 会推荐       | 主动转发/在社群提及               |

### 1.3 缩进假说（xyz）：可立即测试的假说

从 XYZ 缩进到**可触达、可在一两周内测试**的 y 与具体场景：

- **Y → y**：「创业者、独立开发者、产品经理」缩进为「某创业社群/孵化器成员」「某独立开发者 Discord/微信群成员」「某公司产品团队」「某产品经理/创客社区（如即刻、小红书、知乎相关话题关注者）」。
- **xyz 假说 1**：在 [某创业社群或某产品经理/开发者社群] 中，至少 10% 的成员在看到 Skill 介绍或演示后，会**至少使用 1 次**（输入一个想法并获取指南），或**留已验证邮箱**以获取更新。
- **xyz 假说 2**：在已使用过该 Skill 的 y 中，至少 20% 会**再次使用**（用第二个想法验证），或**付费**（如 9～49 元）获取高级版/模板库，或**主动推荐**给他人。

**样本与代表性说明**：  
y 需能代表 Y——有产品创意、会验证、使用 AI 工具。样本量建议约 100～1 000；若从社群、社区切入，须确保成员确有「验证想法」的场景与动机。避免仅用亲友或无代表性的小样本。

## 二、预型工具：预型验证方案

本部分对应原著第 5 章。Agent Skill 属软件类，适合用**假门预型**（先测谁想要）+ **假面预型**或**土耳其机器人预型**（人工或简化版交付）组合验证。

### 2.1 推荐的预型类型及理由

- **推荐**：**假门预型 + 假面预型**（或 **假门 + 土耳其机器人**）组合
- **理由**：
  1. **假门预型**：Skill 尚未完善或未正式发布时，设「正门」——如落地页「产品创意验证 Skill 即将上线」「留邮箱抢先体验」、或在 Cursor/社区发帖「我做了个验证想法的 Skill，有兴趣的留邮箱」。收集谁敲门、多少人敲门。低成本验证需求是否存在。
  2. **假面预型**：当有人「敲门」时，**有人回应、有事发生**——你手动或用简化版 AI 为其生成一份验证指南（人工扮演「Skill」），交付给用户。用比假门更高的投入，换取「用户会不会真用、用完会不会回来、会不会付费」的 YODA。
  3. **土耳其机器人预型**（可选）：Skill 尚未自动化时，用户以为在调用 Skill，实际幕后由你（或另一 AI）根据输入手动生成指南。验证用户会不会用、用几次、用完是否满意、是否愿意付费。零代码即可模拟完整体验。
- **原著依据**：techniques.md 中假门——「产品/服务尚未存在，想先验证有多少人感兴趣、谁感兴趣」；假面——「有人回应、有事发生，客户甚至可能真的拿到东西」；土耳其机器人——「技术尚未开发或需多年+大量资金才能做出原型时，想先验证人们会不会用、怎么用」。

### 2.2 实施方案概要

1. **准备**
   - **假门**：制作落地页或社群帖子，文案如「产品创意验证 Agent Skill 即将上线 / 留邮箱抢先体验」，附简短演示（截图或 30 秒录屏：输入想法 → 输出指南）。通过创业社群、产品经理群、独立开发者 Discord/微信群、即刻/小红书等渠道投放。
   - **假面 / 土耳其机器人**：准备「门后」能力——当用户留邮箱或直接发来想法时，你（或简单脚本+人工）为其生成一份验证指南并交付。可先用现有 pretotyping 流程手动执行，或搭一个最简单的「表单提交 → 人工回复」流程。

2. **执行**
   - **假门**：投放链接/帖子，记录触达人数、留资人数、来源渠道；对「敲门」者邀请参与假面体验。
   - **假面 / 土耳其机器人**：用户提交想法后，你在 24～48 小时内交付一份验证指南（可基于现有 pretotyping 模板）；观察用户是否回复、是否再次提交、是否询问付费版或推荐给他人。可选：对部分用户收小额费用（如 9 元）测试付费意愿。

3. **数据收集**
   - 记录：假门——多少人留资、谁留资；假面/土耳其机器人——多少人完成至少 1 次使用、多少人再次使用、多少人付费、多少人推荐。
   - 仅**伴随切身利益**的行为计为有效 YODA：使用（时间投入）、留资、付费、推荐（注意力/社交资本）。见第 6 章切身利益卡尺。点赞、口头「好用」不计。

4. **周期与成本**
   - 假门：1～2 周可完成首轮；成本极低。
   - 假面/土耳其机器人：每批 10～50 人可在 2～4 周内完成；成本为人工时间，尽量控制在预型量级。

### 2.3 可参考的原著案例

- **凯文·凯利旅游指南**（假门预型）：杂志广告卖 1 美元旅游指南目录，当时无库存；订单够再去做。启示：假门可快速验证「多少人会敲」；本创意可先设「留邮箱抢先体验」，看多少人留资。
- **CarsDirect**（假面预型）：网站上线时手头无车；有人下单就去经销商处买车再交付，亏本换 YODA。启示：假面可验证「真交付后用户反应」；本创意可对留资用户手动交付验证指南，观察是否满意、是否复购或付费。
- **IBM 语音转文本**（土耳其机器人预型）：隔壁房间打字员模拟「电脑听写」，用户以为电脑在转写。启示：人工模拟复杂功能，零技术即可验证「会不会用、用多久」；本创意可人工扮演 Skill，验证用户是否会持续使用、是否愿意付费。
- **《火星救援》与小说预型**（5-12）：免费连载→粉丝阅读、编辑、提建议→0.99 美元电子书→大获成功。启示：先给「小甜头」再要求切身利益；本创意可免费提供 1～2 次验证，再引导付费或推荐。

## 三、分析工具：如何分析和理解数据

本部分对应原著第 6 章。说明哪些数据算有效 YODA、如何用 TRI 计量仪诠释结果、需要多少次试验、如何做决策。

### 3.1 哪些数据算有效（切身利益卡尺）

- **本方案中，用户将收集的行为**：使用 Skill 至少 1 次（时间投入）、留已验证邮箱、支付小额费用（如 9～49 元）、主动推荐给他人（转发、群内提及）。
- 根据原著表 6-1，这些行为**伴随切身利益**（时间、金钱、注意力），有分数，可作为 YODA。
- **不算**有效验证依据的：口头「好用」「有意思」、点赞、未验证的留资、问卷调查「你会用吗？」「你愿意付多少钱？」等（均为 0 点）。

### 3.2 如何用 TRI 计量仪诠释结果

- 将**每次**预型试验的结果，对照 xyz 假说（如「至少 10% 会使用或留资」「至少 20% 会复购或付费」），映射到五个层级之一：
  - 数据**大大超过**假说预测 → **非常有可能**
  - 数据**达到或略超**假说预测 → **有可能**
  - 数据**略低于**假说预测 → **不可能**
  - 数据**远低于**假说预测 → **非常不可能**
  - 数据模糊或受干扰 → **50/50** 或丢弃该次
- 只有**与切身利益相关的 YODA** 才有资格标在 TRI 计量仪上。

### 3.3 试验次数建议

- **至少 3～5 次**预型试验（不同 y、不同渠道、不同话术或不同交付方式）；若涉及重大投入（如全职开发、大额推广），建议再多几次。
- **一次试验无论结果多好或多差都不足以下结论。** 可先做假门 1～2 轮，再做假面/土耳其机器人 2～3 批，综合判断。

### 3.4 决策：继续、转型或停止

- 根据多次试验在 TRI 计量仪上的**整体分布**做判断：
  - 多数箭头落在「有可能」或「非常有可能」→ 有较充分证据支持继续推进；仍须结合你要投入的切身利益权衡。
  - 多数落在「不可能」或「非常不可能」→ 应回到绘图板，调整创意（如改目标用户、改定价、改交付形式、改为免费+增值）或换方向。
- 书中未给出单一公式或固定分数线；决策依赖整体证据与自身风险承受度。

### 3.5 常见陷阱提醒

- **虚荣指标**：只看「多少人下载」「多少人点赞」「多少人说好用」，不看使用次数、留资、付费、推荐等切身利益行为。
- **过早下结论**：只做一批假面就下结论「市场验证通过」或「没人要」。
- **追踪意见而非行为**：问「你会用吗？」「你愿意付多少钱？」而非看人们是否真的使用、留资、付费。
- **忽视复购与推荐**：Skill 类产品依赖「用了还会用」「用了会推荐」；若只有一次性使用而无复购或推荐，长期价值存疑。
