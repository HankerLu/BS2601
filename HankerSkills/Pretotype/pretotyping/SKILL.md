# Pretotyping（预型验证）技能 V2

运用《做对产品》中的Pretotyping方法论，将产品创意转化为可执行的验证方案。

## 核心功能

**输入**：用户的产品创意（任意详细程度）
**输出**：标准化的三部分验证方案

## 工作流程

### 第一步：收集产品创意

接受用户以任何格式描述的产品创意：
- 简单版："我想做一个AI健身教练"
- 详细版：包含目标用户、功能特性等的完整产品描述

### 第二步：补充缺失信息（最多2轮）

如果信息不足，提出澄清问题：

**第1轮问题**（仅在需要时提问）：
- 这个产品解决什么问题？
- 目标用户是谁？
- 用户会采取什么行动来使用它？

**第2轮问题**（仅在仍有需要时提问）：
- 你认为有多少比例的目标用户会使用？
- 产品形态是什么？（app/网站/实体产品/新功能等）

**重要提示**：不要强迫用户回答所有问题。如果用户提供的信息有限，可基于合理假设生成方案。

### 第三步：生成标准化输出

使用 `templates/output_template.md` 中的模板，创建包含三个部分的完整验证方案：

#### 第一部分：XYZ市场验证假设（详细版）

将创意转化为可量化的假设：
- **X**：预期转化率（附论证依据）
- **Y**：目标用户群体（具体的人群特征、痛点）
- **Z**：目标行为（可衡量的、有实际投入的行为）
- 验证标准（样本量、成功阈值、时间范围）
- 关键风险假设

#### 第二部分：预型实施方案（详细版——重点部分）

提供可执行的、本地化的验证方案：
- **推荐技术**（从7种预型验证技术中选择）
- **分步检查清单**（4个阶段：准备、搭建、触达用户、收集数据）
- **中国本地化**（微信、小红书、抖音等）
- **资源清单**（模板、工具、示例）
- **成本与时间估算**（切合实际的明细）
- **常见问题**（常见问题及解决方案）

#### 第三部分：YODA数据评估指南（精简版）

帮助用户用自己的数据评估结果：
- **YODA原则**（Your Own DAta——只相信真实行为数据）
- **投入度量表**（金钱 > 时间 > 精力 > 口头表态）
- **TRI框架**（思考-优化-迭代的决策逻辑）
- **快速决策工具**（输入数据 → 获得继续/转型/停止建议）

## 技术选择逻辑

根据产品类型匹配合适的预型验证技术：

| 产品类型 | 首选技术 | 备选技术 |
|---------|---------|---------|
| SaaS / Web应用 | 皮诺曹（落地页） | 假门面 |
| 移动App | YouTube原型 | 单一功能版本 |
| AI / 自动化产品 | 机械土耳其人 | 皮诺曹 |
| 实体产品 | 纸板原型 | 众筹预售 |
| 新功能（现有产品） | 假门面 | 单一功能版本 |
| 硬件 / 物联网 | YouTube原型 | 众筹预售 |

**选择标准**：
1. 产品复杂度
2. 可用资源（时间、资金、技能）
3. 目标用户的可触达性
4. 所需验证强度

## 核心原则

### ✅ 应该做

1. **即使输入信息很少也要生成完整方案**
2. **实施步骤要具体**（精确到工具、平台、成本）
3. **本地化**适配用户所在市场（默认为中国市场）
4. **尽可能提供模板**和示例
5. **设定切合实际的预期**（时间和成本）

### ❌ 不应该做

1. **不要问太多问题**（最多2轮）
2. **不要留占位符**（用合理假设填充）
3. **不要太笼统**（"利用社交媒体" → 明确指出"小红书、知乎"）
4. **不要跳过成本估算**（始终提供范围）
5. **不要忽略本地化**（工具、平台、语言）

## 使用示例

### 场景1：最少输入

**用户**："我想做一个帮助职场人学编程的产品"

**Agent**：
1. 提出1-2个澄清问题
2. 基于假设生成完整方案
3. 使用模板输出全部三个部分

### 场景2：详细输入

**用户**：[提供包含目标用户、功能特性、定价等的完整产品描述]

**Agent**：
1. 跳过澄清问题
2. 基于提供的信息生成完整方案
3. 使用模板输出全部三个部分

### 场景3：用户已有测试结果

**用户**："我已经测试了2周，有数据了"

**Agent**：
1. 询问数据（曝光量、转化数、预期比率）
2. 运行 `scripts/data_analyzer.py` 的逻辑
3. 提供继续/转型/停止的建议及下一步行动

## 输出质量标准

每份生成的方案应该：

✅ **可执行** - 用户可以立即开始行动
✅ **具体明确** - 提及具体的工具、平台、成本
✅ **本地化** - 适合用户所在市场
✅ **切合实际** - 对时间和成本诚实
✅ **内容完整** - 三个部分全部填写完毕（无待定/待办项）

## 常见场景

### 用户不确定转化率

提供行业基准数据，建议使用保守估计（大多数情况下5-10%）

### 用户没有预算

聚焦免费渠道和工具，提供"零成本"替代方案

### 用户没有技术能力

推荐无代码工具，提供分步教程，建议使用机械土耳其人技术

### 用户想测试多个创意

为每个创意分别生成方案，建议依次测试（而非同时进行）

## 与脚本的集成

虽然主要输出是markdown方案，但你可以借助脚本：

1. **XYZ假设** - 使用 `xyz_hypothesis.py` 的逻辑计算样本量
2. **数据分析** - 当用户有结果时，运行 `data_analyzer.py` 的逻辑
3. **决策矩阵** - 使用 `decision_matrix.py` 生成可视化框架

**注意**：不要要求用户手动运行脚本，将逻辑整合到你的输出中。

## 成功指标

一份好的验证方案应能让用户：
- 在3天内启动验证
- 在1-2周内完成测试
- 花费 < ¥1000（理想情况 < ¥500）
- 得到明确的继续/转型/停止决策

---

**切记**：目标是帮助用户在投入全面开发之前，快速且低成本地验证创意。每份方案都应体现"用一周验证想法，避免一年的弯路"。
