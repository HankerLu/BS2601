# Pretotyping 产品想法验证技能

本技能基于《做对产品》方法论，帮助您将产品想法转化为可验证的假设，设计低成本验证方案，并指导如何基于一手数据判断市场假设是否成立。

## 核心流程

本技能遵循统一的输出模板，包含三个部分：

1. **第一部分：XYZ 假设** - 将产品想法量化为可验证的假设
2. **第二部分：Pretotype 技术匹配与实施方案** - 设计低成本验证方案
3. **第三部分：数据验证指导** - 基于 YODA 数据判断假设成立性

## 输入引导（最多 2 轮追问）

### 初始输入

请用户提供产品想法的基本描述，包括：
- 想要做什么产品？
- 解决什么问题？
- 目标用户是谁？

**如果用户输入信息已足够完整**，直接进入输出生成。

**如果用户输入信息不足**，进行追问引导：

### 第一轮追问（如需要）

如果初始输入缺少以下关键信息，请询问：

1. **目标用户**：您的产品面向哪些人群？具体特征是什么？（如：年龄、职业、痛点等）
2. **核心价值**：这个产品最大的价值是什么？用户为什么要用它？
3. **期望行动**：您希望用户采取什么行动？（如：注册、购买、下载等）

### 第二轮追问（如需要）

如果仍有信息缺失，请询问：

1. **转化率目标**：您认为合理的转化率目标是多少？（如：5%、10%等）
2. **资源限制**：您在时间、预算、技术能力方面有什么限制？
3. **测试场景**：计划在什么场景下测试？线上还是线下？

**追问规则**：
- 最多追问 2 轮
- 每轮追问不超过 3 个问题
- 追问后，基于现有信息生成输出（不要求用户必须提供所有细节）

## 输出生成流程

### 步骤 1：生成第一部分 - XYZ 假设

**生成方法**：基于用户提供的想法和追问获取的信息，智能体直接生成 XYZ 假设。

**XYZ 假设格式**：
```
至少 X% 的 Y（目标用户）会 Z（采取行动）
```

**计算方法**：

1. **确定 X（期望转化率）**
   - 如果用户明确提供了转化率目标，直接使用
   - 如果未提供，根据产品类型和行业标准估算：
     * 新产品/创新产品：3-5%
     * 改进型产品：5-10%
     * 必需型产品：10-20%
   - 给出估算依据和理由

2. **确定 Y（目标用户）**
   - 基于用户描述，精确定义目标用户
   - 考虑年龄、职业、地域、兴趣等维度
   - 确保描述具体且有明确边界

3. **确定 Z（期望行动）**
   - 明确用户需要采取的具体行动
   - 行动必须可衡量、可观察
   - 常见行动示例：注册、购买、下载、订阅、分享等

4. **计算最小样本量**
   - 使用简化公式：n = (Z² × p × (1-p)) / e²
   - 其中 Z=1.96（95% 置信度），p=转化率，e=0.05（误差范围）
   - 给出估算结果和计算依据

5. **确定成功阈值**
   - 成功阈值 = 样本量 × 转化率
   - 例如：100 人 × 5% = 至少 5 人转化

**输出格式**：

```markdown
## 第一部分：XYZ 假设

### 假设描述
至少 X% 的 Y（目标用户）会 Z（采取行动）

### 验证标准
- 最低转化率：X%
- 目标用户：Y
- 目标行动：Z
- 最小样本量：N 人（计算依据：[说明]）
- 成功阈值：在 N 次曝光中至少 M 次转化
- 建议测试周期：1-2 周
```

### 步骤 2：生成第二部分 - Pretotype 技术匹配与实施方案

**生成方法**：基于产品类型、XYZ 假设和用户资源限制，智能体分析并推荐最合适的 Pretotype 技术。

**技术匹配逻辑**：

1. **分析产品类型**
   - 根据用户描述识别产品类型：
     * SaaS / 网页应用 → 皮诺曹落地页、假门面
     * 移动应用 → YouTube 原型、单一功能
     * AI / 自动化服务 → 机械土耳其人
     * 实体产品 / 硬件 → 纸板原型、众筹
     * 新功能 / 特性 → 假门面、A/B 测试

2. **评估资源限制**
   - 成本限制：极低（< 50 元）、低（50-500 元）、中（500-2000 元）、高（> 2000 元）
   - 时间限制：1 周内、1-2 周、2-4 周、1 个月以上
   - 技术能力：基础（无编程经验）、中等（会简单开发）、高级（专业开发）

3. **选择最优技术**
   - 优先选择满足资源限制的技术
   - 优先选择成本低、时间短、技术要求低的技术
   - 考虑 XYZ 假设的特点，选择最能验证假设的技术

**7 种 Pretotype 技术参考**：

1. **皮诺曹落地页**
   - 适用：SaaS / 网页应用
   - 成本：0-50 元
   - 时间：1-3 天
   - 技术要求：基础
   - 说明：创建看起来像真实产品的落地页，但后台没有实际功能

2. **假门面**
   - 适用：新功能 / 特性测试
   - 成本：0 元
   - 时间：1 天
   - 技术要求：基础
   - 说明：在现有产品上添加假的入口，测试用户兴趣

3. **YouTube 原型**
   - 适用：移动应用
   - 成本：0 元
   - 时间：1-2 天
   - 技术要求：基础
   - 说明：通过视频演示产品概念，测试用户兴趣

4. **机械土耳其人**
   - 适用：AI / 自动化服务
   - 成本：0-100 元
   - 时间：1-2 周
   - 技术要求：中等
   - 说明：前端看起来自动化，但后台由人工处理

5. **纸板原型**
   - 适用：实体产品 / 硬件
   - 成本：50-200 元
   - 时间：1-3 天
   - 技术要求：基础
   - 说明：使用纸板、打印材料等创建物理原型

6. **众筹测试**
   - 适用：新产品 / 创新产品
   - 成本：0-5000 元
   - 时间：2-4 周
   - 技术要求：中等
   - 说明：通过众筹平台测试市场需求和付费意愿

7. **单一功能**
   - 适用：SaaS / 移动应用
   - 成本：0-500 元
   - 时间：1-2 周
   - 技术要求：中等
   - 说明：只实现一个核心功能，验证核心价值

**实施方案生成**：

根据选择的技术，生成详细的实施方案，包括：

1. **具体步骤**（6 步详细流程）
   - 准备阶段：需要做哪些准备工作
   - 内容阶段：如何创建核心内容
   - 设计阶段：如何设计产品界面/原型
   - 部署阶段：如何发布和推广
   - 跟踪阶段：如何收集数据
   - 优化阶段：如何根据反馈调整

2. **数据采集方案**
   - 采集指标：需要跟踪哪些关键指标
   - 数据来源：如何获取这些数据
   - 工具建议：推荐哪些免费或低成本工具
   - 成本预估：时间和金钱成本

3. **时间安排**
   - 按天或按周的具体时间线
   - 每个阶段的主要任务

### 步骤 3：生成第三部分 - 数据验证指导（简略版）

**生成方法**：基于《做对产品》的切身利益卡尺和 TRI 计量仪，提供数据验证指导。

**验证方法说明**：

1. **切身利益卡尺评估**
   - 需求强度：高频刚需（9-10 分）> 低频刚需（6-8 分）> 偶发需求（3-5 分）> 无需求（1-2 分）
   - 痛点程度：必须解决（9-10 分）> 重要但不紧急（6-8 分）> 可有可无（3-5 分）> 没有痛点（1-2 分）
   - 付费意愿：主动付费（9-10 分）> 被动付费（6-8 分）> 犹豫付费（3-5 分）> 不愿付费（1-2 分）

2. **TRI 计量仪量化**
   - T（Target）：目标用户覆盖率 =（目标用户数 / 总样本数）× 100%
   - R（Rate）：转化率 =（转化用户数 / 曝光用户数）× 100%
   - I（Intent）：参与度/意向度 =（高参与用户数 + 有意向用户数） / 总用户数 × 100%
   - TRI 总分 = T × 0.3 + R × 0.5 + I × 0.2

**判断标准**：

- **✅ 继续开发**
  - 满足 XYZ 假设标准（实际转化率 ≥ 目标转化率）
  - 切身利益卡尺评分 ≥ 21 分
  - TRI 总分 ≥ 60 分

- **🔄 调整后重新测试**
  - 实际转化率为目标的 50-99%
  - 切身利益卡尺评分 15-20 分
  - TRI 总分 40-59 分

- **🛑 停止或转型**
  - 实际转化率 < 目标的 50%
  - 切身利益卡尺评分 < 15 分
  - TRI 总分 < 40 分

**输出格式**：

```markdown
## 第三部分：数据验证指导

### 验证方法

#### 切身利益卡尺评估
收集用户反馈后，使用切身利益卡尺评估：
- 用户是否真的需要这个产品？
- 产品是否解决了核心痛点？
- 用户是否愿意为此付费？

评估维度：
- **需求强度**：高频刚需 > 低频刚需 > 偶发需求
- **痛点程度**：必须解决 > 重要但不紧急 > 可有可无
- **付费意愿**：主动付费 > 被动付费 > 不愿付费

#### TRI 计量仪量化
使用 TRI 计量仪量化测试结果：
- **T (Target)**：目标用户覆盖率
- **R (Rate)**：转化率
- **I (Intent)**：参与度/意向度

计算公式：
- T =（目标用户数 / 总样本数）× 100%
- R =（转化用户数 / 曝光用户数）× 100%
- I =（高参与用户数 + 有意向用户数）/ 总用户数 × 100%
- TRI 总分 = T × 0.3 + R × 0.5 + I × 0.2

### 判断标准

**✅ 继续开发**
- 满足 XYZ 假设标准（实际转化率 ≥ 目标转化率）
- 切身利益卡尺评分 ≥ 21 分
- TRI 总分 ≥ 60 分

**🔄 调整后重新测试**
- 实际转化率为目标的 50-99%
- 切身利益卡尺评分 15-20 分
- TRI 总分 40-59 分

**🛑 停止或转型**
- 实际转化率 < 目标的 50%
- 切身利益卡尺评分 < 15 分
- TRI 总分 < 40 分

### 验证指导

收集数据后，按照以下步骤进行验证：

1. 计算实际转化率，与 XYZ 假设的目标转化率对比
2. 使用切身利益卡尺评估用户反馈的质量
3. 计算 TRI 指标，量化测试结果
4. 根据判断标准，决定继续、调整或停止
```

## 常见场景

### 场景 1：用户只有一个模糊想法

**用户输入**："我想做一个健身相关的 app"

**第一轮追问**：
- 您的目标用户是谁？（如：健身新手、健身教练等）
- 主要解决什么问题？（如：没有时间锻炼、不知道怎么锻炼等）
- 期望用户采取什么行动？（如：下载、注册、购买等）

**输出**：基于回答生成完整的 XYZ 假设和技术实施方案

### 场景 2：用户已有较完整的想法

**用户输入**："我想做一个面向 25-35 岁办公室白领的 10 分钟健身 app，用户可以注册免费试用，期望 5% 的注册率"

**输出**：直接生成完整的 XYZ 假设和技术实施方案，无需追问

### 场景 3：用户有 YODA 数据，需要验证

**用户输入**："我已经做了测试，有 200 个访问，12 个注册，期望转化率是 5%"

**输出**：
- 第一部分：回顾原始 XYZ 假设
- 第二部分：跳过（假设已有实施方案）
- 第三部分：提供详细的验证指导，帮助判断假设是否成立

## 注意事项

- **输入引导原则**：尽可能通过追问获取完整信息，但最多追问 2 轮
- **输出完整性**：即使信息不足，也要基于现有信息生成完整的三个部分
- **低成本优先**：所有实施方案必须遵循低成本、省时间、本地化原则
- **量化验证**：所有假设和判断标准必须可量化
- **结果导向**：最终输出要能直接指导用户执行验证测试
- **智能体能力**：完全依赖智能体的理解和生成能力，不使用脚本计算
