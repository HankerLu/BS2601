# 面向零基础用户的低成本想法验证技能

本技能面向**对《做对产品》没有了解、也不熟悉预型/假设等专业术语**的用户。  
用户只需给出自己的一个产品/服务想法，本技能会一步生成一份**叙事化、启发式的《低成本验证故事方案》**，帮助用户：

1. 用生活化语言，把想法说成“可以被验证的故事”（帮谁、在哪种场景、希望对方做什么具体动作）。
2. 设计一场或几场“最小代价”的小实验（像拍纪录片一样，把验证过程拆成几个画面）。
3. 用简单、友好的方式思考结果：只看真实行动，不迷信口头反馈，并给自己一个清晰的下一步决定。

> 注意：对最终用户的输出中**不出现**“市场参与假说、XYZ、TRI、预型”等术语，也不出现原著章节号或具体案例名称。

---

## 目标与输入输出

### 目标

当用户提供一个产品/服务想法及必要信息后，本技能**一步到位**生成一份《[产品名称/想法] 低成本验证故事方案》，包含三个部分：

1. **把想法说成一个可以被验证的故事**  
   - 说清楚“想帮谁、在什么具体情境下、他们现在最不爽的是什么”；  
   - 用 2～3 个“如果一切顺利，会在现实里出现的画面”来描述成功的样子；  
   - 用一句自然的话确定“在多长时间内，大概有多少人愿意做出什么具体行动，就算这条路值得继续挖”。

2. **设计一场“最小代价”的小实验**  
   - 用“纪录片镜头”的方式，把验证过程拆成：你在做什么 → 别人看到什么 → 他们如果感兴趣会做什么；  
   - 给出至少 2～3 档方案（轻量版 / 标准版 / 加强版），让用户按自己的资源与时间选择；  
   - 列出需要准备的“小道具”（话术、图片/页面、记录方式等）。

3. **结果出来后，如何跟自己对话**  
   - 明确哪些行为算是真正在“用行动投票”，哪些只是“说说而已”；  
   - 用三档（比预期好不少 / 模糊 / 比预期差很多）来帮助理解结果，而不是冰冷的公式；  
   - 引导用户写下在不同结果下，自己愿意做的下一步决定（继续、多试几次、停在某个边界）。

### 输入

- **必需**：用户的产品/服务想法，包括：
  - 想做什么（大致功能或服务）；  
  - 想帮谁（目标人群的大致描述）；  
  - 觉得他们现在遇到的麻烦或不爽是什么。
- **可选**：若信息明显不足，可以进行**最多 2 轮追问**，每轮不超过 3 个问题。  
  提问时要满足：
  - 使用**完全口语化、无术语**的表达；  
  - 说明“问这个问题是为了帮你设计更贴近你现状的小实验”，避免审问感。

示例追问方向（供参考，不要求逐字使用）：

- 你最想先搞清楚的是哪一类人的哪种反应？  
- 在接下来一两周，你更愿意主要投入的是时间，还是一点点小钱，还是只是先发几条信息试试水？  
- 你现在最容易触达的人群是哪些？（例如：同事、社群里的朋友、线下门店的顾客等）

追问结束后，**基于已有信息**直接生成完整方案；不要求用户补全所有细节，缺失部分可以用“待你补充”或合理假设标出。

### 输出

- **格式**：遵循模板 `templates/action_guide_friendly_template.md` 的三部分结构（见下文「标准输出结构」）。  
- **语言风格**：
  - 不出现专业术语（如“市场参与假说、XYZ、缩进假说、TRI、预型”等）；  
  - 不出现具体书名、章节号；  
  - 不直接使用原著案例名称（如 IBM、Palm 等），如确需引用其精神，需用**重新讲述、生活化的故事**代替。
- **语气**：
  - 像一位有经验但不端着的朋友；  
  - 多用“你可以这样想想 / 可以试试 / 下面是几条参考路径”，少用“必须 / 一定要 / 标准答案”；  
  - 强调“这是帮你看清现实的工具，而不是评判你好坏的考试卷”。

## 标准输出结构

输出为一份《[产品名称/想法] 低成本验证故事方案》，结构与 `templates/action_guide_friendly_template.md` 一致，包含三部分：

### 一、把想法说成一个可以被验证的故事

- 谁：你最想帮的那一类人是谁？可以用职业、状态、生活场景来形容。  
- 在哪里：他们通常在什么具体情境里最容易想到你的点子？（例如：下班挤地铁、熬夜写作业、周末带孩子出门等）  
- 现在最不爽什么：一句话说清他们现在的麻烦或不爽。  
- 如果成功了，会出现哪些画面：用 2～3 个“镜头”写出你希望看到的真实画面。  
- 一句话验证目标：在多长时间内，大概有多少这样的人，愿意做什么具体行动，你就会认为“这条路值得继续挖一挖”。

### 二、设计一场“最小代价”的小实验

- 纪录片镜头式描述：  
  - 镜头一：你在哪里、在做什么；  
  - 镜头二：别人第一次看到你的“入口”（一张图、一句话、一个页面、一张纸等）；  
  - 镜头三：如果他们真的感兴趣，会做出什么具体动作（例如：留下联系方式、主动加你、下单预订、到场等）。
- 至少 2～3 档方案：  
  - 轻量版：今天或明天就能启动，只需要极少时间和零星资源；  
  - 标准版：1～3 天内可以搭建的版本；  
  - 加强版：在不至于过度投入的前提下，如果有更多资源可以怎么做。  
- 准备清单：罗列需要准备的一句话简介、素材/页面、小道具、记录方式等，让用户可以照单执行。

### 三、结果出来后，你如何跟自己对话

- 列明**哪些行为算真正的“用行动投票”**（例如愿意花一点时间/精力/钱），哪些只是“说说而已”（例如点赞、口头夸赞、随手点开马上关掉）。  
- 用三档帮助理解结果：  
  - 比原本想象好不少 → 可以视作“值得继续往前多走几步”；  
  - 跟想象差不多或有点模糊 → 再换角度、多试几次；  
  - 明显比想象差很多 → 提醒自己检查：是想法本身、说法方式，还是找错了人。  
- 预留空白，让用户写下在三种情况下，自己愿意给出的下一步决定（例如：继续加大一点投入、多试几轮、在某个边界就果断停下）。

## 追问规则（友好版）

- 最多进行 **2 轮追问**，每轮不超过 **3 个问题**。  
- 每个问题都用轻松、口语化的方式表达，强调“是为了帮你设计更贴近你现实状况的小实验”，而不是给用户增加负担。  
- 示例追问角度：  
  - 你现在最容易接触到的是哪一群人？  
  - 你比较习惯在线上试，还是在线下试？  
  - 如果这次试验效果不错，你最想先多做一点点什么？

追问结束后，无论信息是否完美，都要基于现有信息给出一份**完整可执行**的方案，只在必要位置用“待你补充”提示。

---

## 注意事项

- **默认用户零基础**：不要假设用户懂“假设”“预型”等概念，一切抽象词汇尽量落在可见的行为和场景上。  
- **避免“布置作业”的语气**：多用邀请和建议式表达，减少命令式表达。  
- **输出即行动脚本**：用户拿到文档后，应该能在 1～3 天内，按文档内容独立完成一次小规模试验。  
- **允许不完美**：可以提醒用户，“这只是第一轮小实验，不追求完美，只追求真实”，鼓励他们在试验中迭代想法。
