# 产品构思评审工具

## 概述

这是一个帮助C端产品创始人从用户和设计思维角度系统性评审产品构思的工具。通过结构化流程，将模糊的想法转化为可验证、可测量的产品方案。

## 输入输出

**输入**: 用户的项目背景或C端产品idea

**输出**: 完整的产品评审报告，包括：
- 价值主张公式
- 利益相关者地图（可视化）
- 拆解要素及其第一性原理
- 测量方案和闭环标准
- HTML格式的综合报告

## 评审流程

### 步骤1: 收集项目信息

引导用户提供完整的项目背景信息，重点关注：
- **目标人群**: 谁是你的用户？他们有什么特征？
- **使用场景**: 用户在什么情况下会使用？
- **核心问题**: 用户遇到了什么具体问题？痛点是什么？
- **当前方案**: 用户现在如何解决这个问题？有哪些替代方案？
- **产品设想**: 你打算如何帮助用户？核心功能是什么？

提问技巧：
- 使用开放式问题引导用户深入思考
- 追问"为什么"来挖掘本质需求
- 要求具体案例而非抽象描述

### 步骤2: 构建价值主张公式

根据用户提供的信息，使用标准化的价值主张公式：

**公式模板**:
```
帮助（目标人群）在（场景）更好地解决（问题），
主要通过（减少/增加）（拆解要素1）和（拆解要素2）
```

**关键要求**:
- 拆解要素必须基于第一性科学原理，而非解决方案
- 拆解要素应该是可测量、可验证的物理或心理维度
- 避免直接描述功能，而是描述底层机制

详细说明参考 [references/value-proposition.md](references/value-proposition.md)

### 步骤3: 绘制利益相关者地图

基于价值主张和项目背景，识别并映射所有利益相关者：

**关键要求**:
- 绘制**产品未介入**的原始场景，展示用户当前的行为流程
- 识别主要角色和次要角色
- 标注角色之间的交互和反馈循环
- 使用Graphviz DOT语言绘制泳道图

使用以下工具生成可视化：
```bash
# 将DOT代码保存为文件后执行
dot -Tpng stakeholder_map.dot -o stakeholder_map.png
```

参考示例见 [references/stakeholder-map.md](references/stakeholder-map.md)

### 步骤4: 细分拆解要素

基于价值主张中的拆解要素，进一步细分为子要素：

**方法**:
1. 识别主拆解要素的构成维度
2. 应用第一性原理进行分解
3. 建立要素之间的关系公式

**示例**:
```
心理疲劳 = 环境影响 × 动作模式 × 反馈机制 × 感官刺激
```

每个子要素都应该：
- 基于科学理论或可验证假设
- 能够独立测量和优化
- 与用户体验直接相关

详见 [references/element-breakdown.md](references/element-breakdown.md)

### 步骤5: 设计测量方案和闭环标准

为每个子拆解要素制定具体的测量方案：

**测量方案要素**:
- **测量指标**: 使用什么指标量化这个要素？
- **测量方法**: 如何收集数据？（问卷、传感器、行为数据等）
- **测量时机**: 何时测量？频率如何？
- **数据来源**: 从哪里获取数据？

**闭环标准设计**:
- **基线值**: 当前状态的测量值
- **目标值**: 期望达到的改善程度
- **验证方式**: 如何验证解决方案有效性？
- **迭代触发条件**: 何时需要调整方案？

参考 [references/measurement-framework.md](references/measurement-framework.md)

### 步骤6: 生成综合报告

将所有分析结果整合为结构化的HTML报告：

**报告结构**:
```html
<!DOCTYPE html>
<html>
<head>
    <meta charset="UTF-8">
    <title>产品构思评审报告</title>
    <style>
        /* 简洁专业的样式 */
    </style>
</head>
<body>
    <h1>产品构思评审报告</h1>
    
    <section id="overview">
        <h2>项目概述</h2>
        <!-- 项目背景和核心信息 -->
    </section>
    
    <section id="value-proposition">
        <h2>价值主张公式</h2>
        <!-- 标准化的价值主张 -->
    </section>
    
    <section id="stakeholder-map">
        <h2>利益相关者地图</h2>
        <!-- 嵌入可视化图表 -->
    </section>
    
    <section id="element-breakdown">
        <h2>要素拆解分析</h2>
        <!-- 主要素和子要素的详细分解 -->
    </section>
    
    <section id="measurement">
        <h2>测量方案与闭环标准</h2>
        <!-- 每个要素的测量和验证方案 -->
    </section>
    
    <section id="recommendations">
        <h2>关键洞察与建议</h2>
        <!-- 基于分析的产品建议 -->
    </section>
</body>
</html>
```

报告应该：
- 使用清晰的视觉层次
- 包含所有可视化图表
- 提供可操作的建议
- 标注关键风险和假设

## 工作原则

### 1. 保持用户视角
- 始终从用户痛点出发，而非技术可行性
- 使用用户的语言，避免专业术语堆砌
- 通过具体场景验证抽象分析

### 2. 追求第一性原理
- 拆解要素要基于科学原理，而非主观臆断
- 区分"是什么"（本质）和"怎么做"（方案）
- 挑战假设，寻找底层逻辑

### 3. 确保可测量性
- 所有分析结果都应该可以被验证
- 定量指标优先，定性指标辅助
- 建立清晰的因果链条

### 4. 保持批判性思维
- 指出价值主张中的潜在问题
- 识别信息缺口和不确定性
- 提供替代视角和反面论证

## 常见问题处理

### 问题1: 用户无法清晰描述目标人群
**处理方式**: 
- 询问具体案例："能否描述一个具体的用户故事？"
- 使用对比法："这个产品不适合什么样的人？"
- 引导特征描述："你的朋友中谁最需要这个产品？"

### 问题2: 拆解要素过于抽象或是解决方案
**处理方式**:
- 追问"为什么"：持续追问直到找到不可再分的物理/心理维度
- 使用科学语言：将主观描述转化为可测量的科学概念
- 举例说明：提供正确的拆解要素示例供参考

### 问题3: 缺乏竞品或现有解决方案信息
**处理方式**:
- 引导思考："用户现在如何解决这个问题？"
- 扩大范围："不一定是同类产品，可以是替代行为"
- 分析痛点："现有方案的哪些地方让用户不满意？"

## 输出质量标准

完成评审后，检查以下质量标准：

- [ ] 价值主张公式完整且基于第一性原理
- [ ] 利益相关者地图清晰展示原始场景（未介入产品）
- [ ] 拆解要素可被测量和验证
- [ ] 测量方案具体可执行
- [ ] 闭环标准明确可判断
- [ ] 报告结构完整，可视化清晰
- [ ] 提供了关键洞察和可操作建议
- [ ] 标注了关键假设和不确定性
