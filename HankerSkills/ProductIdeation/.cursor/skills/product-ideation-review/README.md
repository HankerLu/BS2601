# 产品构思评审工具 (Product Ideation Review)

## 简介

这是一个帮助C端产品创始人从用户视角和设计思维角度系统性评审产品构思的Agent Skills工具。通过结构化的分析流程，将模糊的产品想法转化为可验证、可测量的方案。

## 适用场景

- 产品构思初期，需要系统性评估想法的可行性
- 已有产品概念，需要从用户角度深度分析
- 需要建立产品的测量和验证体系
- 需要识别产品的关键要素和优先级

## 使用方法

### 在Cursor中自动触发

当你在对话中提到以下关键词时，Agent会自动使用这个skill：
- 产品idea评审
- 价值主张分析
- 用户研究
- 产品构思分析
- 利益相关者分析
- 产品设计思维

### 手动调用

你也可以直接说：
```
"我想用产品构思评审工具来分析我的产品想法"
```

### 准备材料

在开始评审前，准备以下信息会更有效：
1. **项目背景**：为什么想做这个产品？
2. **目标用户**：谁会使用这个产品？
3. **使用场景**：用户在什么情况下会需要？
4. **痛点问题**：用户遇到了什么具体困难？
5. **当前方案**：用户现在如何解决这个问题？

## 输出成果

完成评审后，你将获得：

1. **价值主张公式**
   - 明确的目标人群定位
   - 具体的使用场景
   - 清晰的问题定义
   - 基于第一性原理的拆解要素

2. **利益相关者地图**（可视化）
   - 原始场景（产品未介入）的完整流程
   - 所有相关角色及其行为
   - 角色之间的交互关系
   - 关键痛点和断点识别

3. **要素拆解分析**
   - 主拆解要素的详细分解
   - 基于科学原理的子要素
   - 要素之间的关系模型
   - 优先级分析

4. **测量方案与闭环标准**
   - 每个要素的量化指标
   - 具体的测量方法和工具
   - 基线值和目标值
   - 验证方式和迭代条件

5. **HTML综合报告**
   - 结构化的完整评审报告
   - 所有可视化图表
   - 关键洞察和建议
   - 风险和不确定性标注

## 核心方法论

### 1. 第一性原理思维
不问"怎么做"，而问"是什么"。拆解到不可再分的基本要素，基于科学原理而非主观臆断。

### 2. 用户视角优先
始终从用户痛点出发，而非技术可行性。观察用户行为，而非仅听用户言语。

### 3. 可测量可验证
所有分析结果都应该能够被量化或观察验证。避免无法检验的抽象概念。

### 4. 系统性思维
不孤立地看单一要素，而是理解要素之间的关系和整体动态。

## 示例案例

### 案例1: 运动受限减脂人群的游泳辅助产品

**价值主张**：
```
帮助运动受限型肥胖人群在以减脂为目的的游泳场景中，
更好地解决难以坚持且无痛游完长距离的问题，
主要通过减少心理疲劳感和控制有氧心率
```

**核心洞察**：
- 心理疲劳是比体力疲劳更大的障碍
- 用户频繁查看数据说明需要即时反馈
- 缺乏社会支持（泳伴不总是可得）

### 案例2: 关节术后康复训练辅助系统

**价值主张**：
```
帮助关节术后康复者在居家康复训练中，
更好地解决关节活动度恢复慢且易产生疼痛的问题，
主要通过控制运动负荷强度和提升动作标准性
```

**核心洞察**：
- 康复治疗师无法实时监测居家训练
- 患者对负荷强度的主观判断不准确
- 动作不标准容易导致二次伤害

## 常见问题

**Q: 评审需要多长时间？**
A: 根据信息完整度，通常20-40分钟。如果需要多轮深入探讨，可能需要1-2小时。

**Q: 我的想法还很模糊，可以用这个工具吗？**
A: 可以。工具会通过提问引导你逐步理清思路。模糊的想法正是需要这种结构化分析的。

**Q: 我不是技术背景，能理解这些分析吗？**
A: 可以。所有分析都使用通俗语言，避免过度技术化。科学原理会用简单方式解释。

**Q: 评审结果能直接用于产品开发吗？**
A: 评审提供的是"做什么"（要素和测量），而非"怎么做"（具体功能）。需要进一步的产品设计将要素转化为功能。

**Q: 我已经有产品MVP了，还能用这个工具吗？**
A: 可以。用于验证现有产品是否抓住了核心要素，以及测量体系是否完善。

## 进阶使用

### 与其他工具配合
- **用户访谈**：评审前进行用户访谈，获取更真实的信息
- **竞品分析**：结合竞品的拆解要素分析，识别差异化机会
- **MVP验证**：根据测量方案设计MVP实验，快速验证假设

### 迭代使用
- 产品进入不同阶段时重新评审
- 发现新的用户痛点时补充分析
- 根据实际测量数据调整拆解要素
